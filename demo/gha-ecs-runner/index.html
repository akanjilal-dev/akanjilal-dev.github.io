Reference walkthrough

One build, proven private, gated, and signed

This is one real build on the gha-ecs-runner plane, start to finish. A queued job becomes a single ephemeral Fargate task that builds an image without a Docker daemon, pushes it to Amazon ECR, signs it in the account, and disappears. Then we prove the three things that make it trustworthy.

1  the build is private 2  only the runner can push 3  every image is signed in-account

Unlike the other demos on this site, this one runs on live AWS infrastructure, so it cannot execute in your browser. The commands and outputs below are what the pipeline produces on a real run; the full Terraform, runner image, and control plane are linked so you can stand it up in your own account and reproduce every step. Identifiers are illustrative.

STEP 01

The job queues, a runner appears

A workflow targets the self-hosted labels. The webhook fires over the private API, the scale-up function mints a single-use registration, and exactly one Fargate task starts in a private subnet, tagged with the job it serves.

# a job with runs-on: [self-hosted, ecs, linux, x64] was just queued $ aws ecs list-tasks --cluster gha-ecs-runner --desired-status RUNNING { "taskArns": [ "arn:aws:ecs:ca-central-1:<account>:task/gha-ecs-runner/7b9c1f0a4e2d" ] } $ aws ecs describe-tasks --cluster gha-ecs-runner --tasks 7b9c1f0a4e2d \ --query 'tasks[0].{status:lastStatus,ip:attachments[0].details[?name==`privateIPv4Address`].value|[0],tags:tags}' { "status": "RUNNING", "ip": "10.20.7.143", # private subnet, no public IP "tags": { "github:repo": "demo-app", "github:job_id": "41827733120" } } # the runner registered with its single-use JIT config and picked up one job
STEP 02

The build runs without a daemon, and pushes

Rootless BuildKit builds the image with no Docker socket and no privilege, and pushes straight to ECR using the task role through the credential helper, so there are no registry credentials anywhere in the pipeline.

$ buildctl --addr $BUILDKIT_HOST build --frontend dockerfile.v0 \ --local context=. --local dockerfile=. \ --output type=image,name=$ECR_HOST/demo/app:$GIT_SHA,push=true #1 [internal] booting buildkit (rootless, no daemon) #7 exporting to image #7 pushing layers 2.3s done #7 pushing manifest for ...dkr.ecr.ca-central-1.../demo/app:9f3c2a1 #7 DONE 4.1s $ aws ecr describe-images --repository-name demo/app \ --image-ids imageTag=9f3c2a1 --query 'imageDetails[0].{tag:imageTags[0],pushedBy:imageManifestMediaType}' { "tag": "9f3c2a1", "pushedBy": "application/vnd.oci.image.manifest.v1+json" }
STEP 03

Only the runner can push — everyone else is denied

This is the control that makes “all artifacts are built on our runners” true rather than aspirational. The ECR repository policy allows the push actions only for the runner task role and denies them for every other principal. We try to push the same image as a developer role.

$ aws sts get-caller-identity --query Arn --output text arn:aws:sts::<account>:assumed-role/developer-poweruser/anirban $ docker push <account>.dkr.ecr.ca-central-1.amazonaws.com/demo/app:rogue The push refers to repository [...demo/app] denied: User: arn:aws:sts::<account>:assumed-role/developer-poweruser/anirban is not authorized to perform: ecr:InitiateLayerUpload on resource: ...demo/app because an explicit deny is in the resource-based policy # even with PowerUser/AdministratorAccess on the identity, the repo policy Deny wins. # the ONLY principal that can push is the runner task role: arn:aws:iam::<account>:role/gha-ecs-runner-task
STEP 04

Every image is signed, inside the account

The runner signs the image with an in-account AWS KMS key and the transparency log disabled, so signing touches only KMS and ECR. There is no call to public Sigstore. Deploy targets run exactly this verification before admitting an image.

$ cosign verify --insecure-ignore-tlog=true \ --key awskms:///alias/gha-ecs-runner-signing \ <account>.dkr.ecr.ca-central-1.amazonaws.com/demo/app:9f3c2a1 Verification for ...demo/app:9f3c2a1 -- The following checks were performed on each of these signatures: - The cosign claims were validated - The signatures were verified against the specified public key # no transparency-log lookup, because none was ever written. $ cosign tree <account>.dkr.ecr.ca-central-1.amazonaws.com/demo/app:9f3c2a1 📦 Supply Chain Security Related artifacts ├── 🔐 Signatures for an image tag: ...demo/app:sha256-...sig └── 💾 Attestations for an image tag: ...demo/app:sha256-...att # the SBOM
STEP 05

No public path exists

The runner subnets have no route to an internet gateway or a NAT gateway, the security group egress is capped to the VPC, and every AWS call resolves to a private endpoint. The webhook is a private REST API that does not answer from outside the VPC.

$ aws ec2 describe-route-tables --route-table-ids rtb-runner \ --query 'RouteTables[0].Routes[].DestinationCidrBlock' [ "10.20.0.0/16", "local" ] # no 0.0.0.0/0 — no IGW, no NAT $ aws ec2 describe-security-groups --group-ids sg-runner \ --query 'SecurityGroups[0].IpPermissionsEgress[0].IpRanges[0].CidrIp' "10.20.0.0/16" # egress only to the VPC CIDR $ nslookup api.ecr.ca-central-1.amazonaws.com # from inside the VPC Address: 10.20.5.61 # the interface endpoint, a private IP $ curl --max-time 8 https://<api-id>.execute-api.ca-central-1.amazonaws.com/hook # from the internet curl: (28) Connection timed out # the private REST API does not resolve outside the VPC
STEP 06

The runner vanishes

The job is done, the process exits, and the task stops. There is no scale-down controller, no idle runner left registered, and nothing to compromise between builds. The next job gets its own clean task.

$ aws ecs describe-tasks --cluster gha-ecs-runner --tasks 7b9c1f0a4e2d \ --query 'tasks[0].{status:lastStatus,exit:containers[0].exitCode}' { "status": "STOPPED", "exit": 0 } # runner deregistered from GitHub automatically — the JIT config was single-use. # one task = one job = one signed artifact. capacity reclaimed.
